# 功能开发

适用于新增或改变系统的能力、契约或可观察行为，包括用户、调用方、运维人员或外部系统能够使用或观察到的结果。功能开发的中心是明确目标行为与验收，不是预先指定实现方式。

## 1. 先界定行为

说明目标参与者、调用方或运维角色、触发点、期望结果、主要使用路径、验收条件以及明确不包含的范围。识别异常路径、边界、权限、数据生命周期和兼容性中确实影响本功能的部分。按 [clarification.md](clarification.md) 处理会改变结果的歧义。

## 2. 选择必要产物

局部且规则清晰的功能可直接实现。范围需要锁定时使用 [Scope Contract](../assets/scope-contract.md)；状态、权限或业务规则相互作用时使用 [Spec](../assets/spec.md)；有重要技术取舍时使用 [Design](../assets/design.md)；执行步骤有依赖时使用 [Plan](../assets/plan.md)。不按“简单/普通/复杂”档位打包创建文档。

## 3. 实施

先实现满足验收条件的最小垂直路径，再覆盖必要的失败和边界行为。遵循存量项目惯例；新项目按 [greenfield.md](greenfield.md) 建立最小可运行基础。计划可随调查更新；若已有 Spec 或 Scope Contract，需求行为变化时同步修正。

## 4. 验收

围绕相关参与者、调用方、运维角色或外部系统可观察的成功、失败、权限和兼容场景核验（仅限相关项）。使用项目约定和任务要求的验证方式，避免只以代码编译或任务清单勾选作为完成证明。若验收条件无法验证，明确说明缺口。
