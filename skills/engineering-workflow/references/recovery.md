# 中断恢复

适用于任务被打断、切换会话/模型/Agent，或需要跨时间继续。Recovery 是横切流程：先恢复可信现场，再回到原来的 Bugfix、Feature、Refactor、Migration、Performance 或 Exploration 路线。Checkpoint 是恢复索引，不是事实来源的替代品。

## 恢复步骤

1. **读取最近 Checkpoint**（若存在），提取目标、当前状态、验证、未完成项和下一步。
2. **核对真实现场**：检查工作区、Git 差异、当前分支和关键文件；核对记录是否仍与代码/数据现状一致。不要因文档写着“已完成”就假设现场一致。
3. **验证重要断言**：确认已完成项、验证结果、未决风险与依赖仍成立。区分已核实和陈旧/未验证信息。
4. **回到原任务路线**：如需求或现状已变，先更新范围、Spec 或 Plan；否则继续原来的主流程。完成能独立推进的工作；阻塞项按 [clarification.md](clarification.md) 获取必要信息。
5. **结束时刷新记录**：任务仍未完成且有新的中断风险时更新 Checkpoint；任务已完成或 Checkpoint 已失效则删除/归档该临时记录，遵循项目文档约定。

## 创建 Checkpoint 的时机

仅在工作未完成且上下文连续性有真实风险时创建，例如跨会话交接、长任务暂停或运行环境不稳定。短小且可从代码状态立即恢复的任务通常不需要。

模板见 [../assets/checkpoint.md](../assets/checkpoint.md)。Checkpoint 不得包含密钥、令牌或不必要的个人/敏感数据；关键事实应指向代码、测试、配置或持久文档，而非重复大段内容。
