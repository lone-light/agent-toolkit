# 技术探索

适用于关键问题尚无可靠答案的情况：技术是否可行、方案如何取舍、依赖/平台如何工作，或某种集成方式能否满足约束。探索要回答问题，不是提前实现完整产品。

## 1. 写清待回答的问题

表达一个可判定的问题、相关约束、成功/失败信号以及结论将如何改变后续决策。列出已知事实、假设和最主要风险。若问题其实是目标行为不明确，先读 [clarification.md](clarification.md)。

## 2. 限定实验

选择足以验证假设的最小 Spike、Prototype、文档核查或测量。明确输入、环境、时间/范围边界、与真实数据或外部系统的隔离方式。不要为探索引入不必要的大规模依赖或改造，也不要把实验代码自动视为可上线实现。

## 3. 收集证据并下结论

记录复现步骤、观察结果、未覆盖条件与不确定性。回答原问题：可行、不可行，还是证据不足；说明采用结论的影响与下一步。需要比较方案时用一致标准，区分事实和偏好。

## 4. 转入正式工作

探索结论稳定后，清理或隔离临时产物，按真实目标转入功能、设计、迁移或性能路线。只有会长期影响后续且达到条件的决定才沉淀为 [ADR](../assets/adr.md)；不保存无未来价值的试错流水。
