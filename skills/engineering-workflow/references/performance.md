# 性能优化

适用于降低延迟、提高吞吐、减少资源消耗或解决容量瓶颈。目标是通过可重复证据改善特定场景，同时保持正确性。

## 1. 定义目标和测量条件

明确工作负载、关键指标、目标/阈值（如用户或项目已给出）、环境、数据量、并发量和采样方法。区分用户感知目标与代理指标；没有目标数值时先记录当前基线和比较口径，不擅自编造“达标线”。

## 2. 建立基线并定位

使用适合问题的 profiler、trace、日志、基准或系统指标，重复测量以理解波动。定位证据指向的瓶颈，形成可证伪的假设。不要仅依据代码外观、一次运行或局部微基准推断端到端收益。测量成本过高时，说明替代证据和不确定性。

## 3. 优化和比较

尽量一次验证一个主要变量，避免把多个改动的影响混在一起。比较前后相同场景的结果，并检查相关资源、尾延迟、错误率、容量和正确性。考虑缓存、并发、内存、网络与复杂度之间的代价，不以单一指标退化换取另一指标改善而不披露。

复杂优化按需写 Design 或 Plan；先验证未知的性能假设时读 [exploration.md](exploration.md)。

## 4. 报告

报告基线、测试条件、测量结果、波动/局限与实际变化。若没有可比较的测量，只能称为优化假设或代码调整，不宣称性能提升已得到证明。
