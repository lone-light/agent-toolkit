# 新项目

适用于从零建立产品、服务、应用，或在既有仓库中首次建立尚无稳定实现的独立组件。若宿主仓库已有代码，先完成存量系统的边界调查，再用本流程处理新组件；目标是先形成可验证的最小系统，不要求一开始写完整 PRD 或预先决定所有技术细节。

## 工作步骤

1. **确认目标和使用场景**：谁要完成什么任务，为什么当前方式不够；区分必要结果与实现偏好。
2. **界定第一阶段范围**：列出最小有用交付、不做事项和验收信号。只追问会影响核心行为或风险的未知项，细则见 [clarification.md](clarification.md)。
3. **检查约束**：部署和运行环境、依赖系统、数据敏感性、访问权限、兼容目标、性能或运营要求。区分已确认约束与待验证假设。
4. **决定所需设计深度**：简单原型直接建立骨架；业务规则复杂时写 Spec；方案存在重要权衡时写 Design；跨多步骤实施时写 Plan。不要一次性产出全部 Artifact。
5. **先搭可运行的最小骨架**：使用目标技术栈与必要的端到端路径，避免无依据地引入基础设施或扩展点。
6. **逐步实现和验证**：按验收条件推进。新事实影响后续工作时，调整范围、设计或计划。

## 工程注意事项

- 不把未经验证的假设写成固定需求或架构事实。
- 对外部服务、数据、密钥和部署边界，先确定接口与责任边界，再接入真实环境。
- 先采用仓库或用户已选择的工具和约定；尚未选择且会影响成本、部署或长期维护的技术方案，必要时先做 Exploration。
- 原型与生产要求分开。快速验证用的临时实现，不应在没有评估的情况下被当作生产级实现。
